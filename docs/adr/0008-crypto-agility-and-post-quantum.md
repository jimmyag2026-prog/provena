# ADR 0008: 密码学可替换性与后量子迁移路线

- Status: proposed (定期重新锚定 `--reanchor-days` 已实现) · 2026-10-31

## Context
科研记录要能在几十年后验证。Provena 现在依赖 Ed25519（签名）、X25519（密钥封装）、SHA-256（哈希/承诺/Merkle）、AES-256-GCM（内容加密）。大规模量子计算机会破解 Ed25519/X25519（Shor），对 SHA-256/AES-256 只有平方根级影响（Grover，仍有约 128 位安全）。威胁有两类：
1. **伪造**：未来攻击者伪造历史签名、改写「谁在何时签了什么」。
2. **先存后解**：今天截获的密文与 X25519 封装，未来被解密（对加密数据是真实威胁）。

## Decision
1. **证据靠哈希链续命，不靠签名**：一个条目的存在性与顺序由 SHA-256 Merkle 日志 + 外部时间锚证明；只要在 Ed25519 仍安全时，日志头被一个**哈希型或后量子签名**的锚（或一个仍然可信的 RFC 3161 TSA 用新算法重新盖章）覆盖，旧签名之后被攻破也无法回溯伪造「当时已存在」。动作：Hub 的锚定 worker 支持对历史根之根**定期重新锚定**（re-anchoring），证明包可携带多代锚。
2. **算法即版本**：所有签名结构都带域分隔 tag（`provena/entry/v1` …）与 `v` 字段。新增签名算法 = 新 tag（`provena/entry/v2`）+ agent card 增加 `alg` 与对应公钥字段；验证器按版本分派。旧条目永远按 v1 规则验证。
3. **混合签名过渡**：v2 agent card 同时含 Ed25519 与 ML-DSA-65（FIPS 204）公钥，条目同时带两个签名；验证器在两者都成立时接受。cryptography 库提供 ML-DSA 后实施；浏览器端等 WebCrypto 支持（或以 WASM 实现）前，JS 验证器对 v2 只校验 Ed25519 并给出提示。
4. **加密侧**：项目纪元密钥封装改为混合 KEM（X25519 + ML-KEM-768，FIPS 203），作为一次 `key rotate` 的新 wrap 格式；之后的新内容即获后量子保密。已在旧纪元下加密的内容无法追溯保护——敏感项目应尽早启用。
5. **不改**：SHA-256（Merkle/承诺/cid）、AES-256-GCM 保持；承诺为加盐哈希，不受 Shor 影响。

## Consequences
- 现有 v1 数据永远可验证；迁移是增量的（新 tag、新 card 字段、新 wrap 格式），不需要重写历史。
- 已实现：re-anchoring（`hub serve --reanchor-days`，2026-10-31）。
- 需要实现：v2 条目/卡片格式、混合签名、混合 KEM；JS 验证器跟进。
- 待拍板：触发时间点（建议在 Python 主要密码库稳定提供 ML-DSA/ML-KEM 后的下一个次版本）。
