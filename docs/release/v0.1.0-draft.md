# Provena v0.1.0 — release notes (draft, never tagged; superseded by v0.2.0.md)

**Status: draft for decision.** Tagging is a deliberate human step (`scripts/bump_version.py 0.1.0`,
release PR, tag on `main`). The full list of changes is the `Unreleased` section of
`CHANGELOG.md`; this page is the short version for the release announcement.

> GitHub for code. Hugging Face for models. **Provena for verifiable science.**
> A ledger of experimental data and process, kept encrypted and backed by proof.

## What you can do with 0.1.0

- **Record an experiment** — `provena plan / add / run`: every dataset, preregistered protocol
  and processing step is a signed entry in a per-project Merkle log; content is encrypted on
  your machine (AES-256-GCM, salted commitments). Failed runs are recorded too.
- **Collaborate through a hub** — `remote / push / clone / member`: the hub only sees
  ciphertext, hashes and signatures, issues signed receipts and tree heads, and cannot rewrite
  history without being caught. Mirror a project to a second hub (`provena mirror`); clone
  from it or catch up with `pull --from` while the main hub is down; a witness watching both
  refuses to cosign either side of a fork.
- **Prove and verify** — `prove / verify` (CLI, or drag a `.pvb` onto any hub page): selective
  or full proof bundles, verified offline. The trust level (`self-sequenced` …
  `log-sequenced` … `witnessed` … `anchored`) depends only on the logs, witnesses and RFC 3161
  time-stamp authorities *you* trust. `verify --json` for CI.
- **Share, publish, withdraw** — per-file grants to reviewers, publication with the content
  key, crypto-shredding on consent withdrawal; citations and RO-Crate export.
- **Reproduce** — `rerun` re-executes a recorded step from the ledger alone and records a
  replication attestation (optionally sandboxed).
- **Run a preregistered blind challenge (experimental)** — `challenge init / submit / close /
  score / audit`: the truth is committed before the call and may not be disclosed before the
  deadline; each registered team submits exactly once, on time by hub receipts; the scorer runs
  sandboxed; anyone can audit the published leaderboard without a key.
- **Operate a hub** — SQLite or PostgreSQL, filesystem or S3 blobs, lazy project loading,
  rate limits, `/healthz` and Prometheus metrics, Docker, witnesses and anchoring.

## Security

Fifteen independent adversarial and regression reviews and a red-team pass ran during development; every
confirmed finding is fixed with a regression test (see `CHANGELOG.md` → Security and
`docs/THREAT_MODEL.md`, threats T1–T25). Known limits are documented in the threat model,
including: Provena proves the integrity, authorship, order and time of *records*, not that the
data reflects reality; on macOS a sandboxed program can still read same-user processes'
environments (do not set `PROVENA_PASSPHRASE` when running untrusted code).

## Compatibility and status

- Python 3.11+ (tested on 3.11 and 3.12). Formats: entries v1, proof bundles `provena-bundle/1`
  (`docs/spec/bundle-v1.md`), verify output `provena-verify/1`.
- 0.x: formats may still change; an incompatible change gets a new format identifier
  (`provena-bundle/2`), never a silent reinterpretation of `/1`.
- Sandboxes: macOS `sandbox-exec` and Linux bubblewrap are both exercised end to end (bubblewrap in
  CI on Ubuntu with unprivileged user namespaces enabled).
