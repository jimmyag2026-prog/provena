# Provena v0.2.0 — release notes (2026-10-31)

The first tagged release (0.1.0 was never tagged; its draft is kept for history). The full list of
changes is the `[0.2.0]` section of `CHANGELOG.md`; this page is the short version.

> GitHub for code. Hugging Face for models. **Provena for verifiable science.**
> A ledger of experimental data and process, kept encrypted and backed by proof — written by
> agents first, read by anyone.

## What is new since the 0.1.0 draft

- **An agent contract** (`docs/spec/cli-contract-v1.md`): `provena --json` envelopes on every
  command, exit codes 0–7 by kind of failure, passphrase files, idempotent retries, `#N` / prefix
  / path references, structured `verify --json`.
- **Agent entry points**: `provena mcp` (MCP server over stdio), SDK `record` / `verify`,
  in-toto / DSSE export, verify badges and a GitHub Action. **Spark Research** records every task
  and tool call into a Provena ledger automatically.
- **Ledger rules 2** (ADR 0009): history keys for late members, provable step status and details,
  publishing a content key later; one rules table shared by both verifiers.
- **Hubs**: signed log-key hand-over (ADR 0010), orgs / quotas / API keys and schema migrations
  (ADR 0012), replay snapshots, C2SP checkpoints for transparency-log witnesses, a JSON twin of
  every page.
- **Readers**: the hub's front end is a single-page app that checks a project's whole log, or one
  cited entry, in the reader's browser; server-rendered pages remain under `/classic`.
- **Challenges**: the rules live in `provena.core.challenge`, shared by the CLI and the hub, whose
  leaderboard page re-checks every row against its own logs and receipts; a challenge project can
  no longer void itself by accident.
